# Trial 3 설계 — Qwen3-VL-8B 24-way 판별기 (목표: LB 0.9+)

날짜: 2026-07-17 · 마감: 2026-07-24 23:59 KST (7일, 제출 14회 잔여)
예산: vast.ai 총 **$15 이내**

## 1. 배경과 목표

- 태스크: 캡션 + 뒤섞인 4프레임 → 시간 순서 복원. 24개 순열 exact match.
- trial2: Qwen2.5-VL-7B QLoRA(4-bit), masked SFT, **0.28 epoch 중단**, greedy 추론
  → 로컬 val 0.4167 / **Kaggle LB 0.7**.
- val↔LB 갭의 원인: train에 조직위 명시 노이즈(검은 프레임, 순서 특정 불가) 포함,
  test는 상대적으로 깨끗 → 로컬 val이 실력을 과소평가.
- 목표: **LB 0.9+**. 정직한 예상: SFT 완주+클리닝+TTA 0.82~0.88, ranking loss 작동 시 0.9+.

## 3. 모델 결정: Qwen3-VL-8B-Instruct (확정)

- 근거: 2026-05-31 컷오프 내 최신 세대, 멀티이미지/시간 이해 강화,
  transformers 네이티브 + peft 지원(파인튜닝 마찰 최소), 3090 bf16 수용.
- 왜 더 큰 모델이 아닌가: 바인딩 제약은 추론(24GB, 105s/행)이 아니라 **학습 예산 $15**.
  32B는 1 epoch도 예산 초과 + 4-bit 추론 강제. trial2 실측상 이 태스크는
  fine-tune 이득(0.17→0.42 @0.28ep) >> 모델 크기 이득 → "잘 튜닝된 8B bf16 > 설익은 32B 4-bit".
- 폴백: Qwen3-VL-8B 통합 실패 시 Qwen2.5-VL-7B bf16 (trial2 검증 경로).

## 4. 방법론

### 4.1 정밀도 — bf16 일관, 양자화 없음
- 추론 VRAM 추정: 가중치 ~18GB + KV(1.3~2.3k 토큰, GQA) ~0.2-0.4GB + 활성값 ~2GB
  = 피크 ~20-21GB < 24GB. **3090 리허설 실측이 최종 판정**; 22GB 초과 시에만
  int8 weight-only 폴백 (4-bit는 어떤 경로에도 없음).
- 학습: A100 80GB에서 bf16 LoRA (QLoRA 아님 — trial2의 4-bit는 3090 시절 관성).
- 학습 정밀도 = 추론 정밀도 → 분포 미스매치 제거.

### 4.2 데이터 — 클리닝 + 클린 val
- 노이즈 탐지(휴리스틱, train만 사용): 검은/근검은 프레임, 중복/근중복 프레임,
  (선택) 저신뢰 라벨. trial2의 `clean_data.py`를 출발점으로 확장.
- **클린 val** (~1000행): 필터 통과 샘플만으로 구성 → 테스트 분포에 근접, LB 예측력 확보.
  Day 1 calibration 제출로 val↔LB 매핑 실측.
- 학습셋에도 동일 필터 (노이즈 라벨은 ranking loss에 특히 유해).
- No_ordering=True(1,478행, 정답 [1,2,3,4])는 유지하되 증강 시 취급 주의 (5.2 참조).

### 4.3 학습 — 2단계
- **Stage 1: masked SFT 웜스타트** (~1 epoch): trial2 검증 방식.
  answer completion 토큰만 감독. LoRA r=32~64, all-linear, cosine LR + warmup.
- **Stage 2: listwise ranking** (~1-2 epoch): 24개(또는 메모리 제약 시
  정답 + 하드 네거티브 7개, 인접 스왑 우선) 후보 답안의 logprob에 softmax CE.
  프롬프트 forward 1회 + KV 공유로 후보 continuation 병렬 계산.
  추론 결정 규칙(24-way argmax)과 목적함수를 일치시키는 것이 핵심.
- 셔플 증강: 매 epoch 각 샘플의 프레임 제시 순서 재셔플(라벨 동시 변환)
  → 위치 편향 구조적 차단 + 실질 데이터 확대.
- 클린 val exact-match로 주기 평가, best checkpoint 유지.
- 헤지: Stage 2 실패 시 Stage 1 체크포인트로 제출 가능 (sunk cost ~$3).

### 4.3.1 체크포인트 · 로깅 · 중간 제출 (요구사항)
- **체크포인트**: N스텝마다(≈15-20분 간격) LoRA 어댑터 저장 (`ckpt-{step}/`).
  best(클린 val 기준) + 최근 3개 유지. 어댑터 ~100-300MB → scp로 즉시 이동 가능.
- **로그**: JSONL 학습 로그 (step, loss, lr, 시간) + 주기적 클린 val exact-match
  + 콘솔 tail 가능한 진행 로그. tmux 세션에서 상시 확인.
- **중간 추론/제출 경로**: `infer.py`가 `SNU_ADAPTER_DIR`로 임의 체크포인트를 받아
  test.csv → 제출 CSV 생성. 학습 중인 A100과 **별도의 3090 박스**(~$0.2/h)에서 실행
  → 학습 중단 없이 아무 시점의 체크포인트로 제출 CSV 생성 가능.
- 첫 중간 체크포인트 제출이 **val↔LB calibration** 데이터를 겸함.

### 4.4 추론 — constrained scoring + 등변 TTA
- 24개 순열 후보의 logprob argmax (greedy 아님; trial2에서 greedy 대비 우위 확인).
- 프롬프트 KV 공유로 24후보 병렬 스코어링 → ~2-4s/샘플.
- **TTA**: 제시 순서 k=6가지로 반복, 점수를 원 라벨 공간으로 역변환해 합산
  → 위치 편향 상쇄. 총 ~20s/샘플, 819행 ≈ 4.5h.
- 해상도: 학습/추론 max_pixels 상향 (품질 우선; A100 학습 수용 한도 내에서 결정,
  추론은 3090 리허설로 상한 실측).

### 4.5 대회 스펙 리허설
- vast.ai에서 RTX 3090 24GB 대여, **오프라인 모드로** 전체 819행 추론 실행.
- 실측 항목: VRAM 피크, 총 소요시간, TTA k 상한, 해상도 상한.
- 산출물은 본선 보고서의 "자원 효율성/최적화" 항목(20점) 증빙으로 재사용.

## 5. 일정 · 예산 — 메인 세션 6시간 컷

기존 trial2 어댑터 재활용 제출은 하지 않음 (새 트라이로 즉시 시작).
Stage 2 ranking은 6h 밖 — 시간이 남거나 2일차에 잔여 예산으로 수행.

| 시각 | 작업 | 어디서 | 비용 |
|---|---|---|---|
| H0–0.5 | vast 박스 대여 시작(A100), 클리닝 스크립트 실행(로컬), 학습/추론 코드 작성 | 로컬+A100 | — |
| H0.5–1.5 | 데이터 업로드 + Qwen3-VL-8B 다운로드 + 스모크 테스트(마스킹·스코어링 검증) | A100 | ~$1 |
| H1.5–4.5 | **Stage 1 SFT** (클리닝+셔플 증강, ~2 epoch), 15-20분마다 ckpt+val 로그 | A100 (tmux) | ~$4 |
| H2.5– | 병렬: 3090 대여 → 중간 ckpt 추론 → **1차 제출 CSV** (calibration 겸용) | 3090 | ~$0.5 |
| H4.5–5.5 | best ckpt 전체 추론 (constrained scoring + TTA k=2-4) → **2차 제출 CSV** | 3090 or A100 | ~$1 |
| H5.5–6 | CSV 형식 검증, 제출 인계, 박스 반납 | 로컬 | — |
| 합계 | | | **~$6.5** |

이후 (선택, 잔여 ~$8): 2일차에 Stage 2 ranking + TTA k/해상도 상향 + 3090
대회 스펙 리허설(본선 증빙) → 0.9 돌파 시도. 제출은 일 2회 페이스로 소진.
